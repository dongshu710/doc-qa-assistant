## 二、P0 · 亟待处理

### P0-1 设置面板把「用户输入」变成了「服务端出站请求」的入口

- **位置**：`src/server.py` `_probe_llm()`（约 250 行附近）、`src/appconfig.py` `_check_base_url()`
- **现象**：`base_url` 只校验「是 http(s) 开头」，随后服务端直接 `POST {base_url}/chat/completions` 并回显状态码与延迟。
- **影响**：能改设置的人可以让服务去请求任意地址——`127.0.0.1:6379`、内网管理口、
  云厂商元数据地址（`169.254.169.254`）。响应码与延迟差异足以做端口/服务探测。
- **当前边界**：修改类接口只允许本机（`_client()` 判定），所以风险被压在单机内。
  **但**：一旦服务绑 `0.0.0.0`、或配了 `ADMIN_TOKEN` 分享给别人，这条路径立刻成为内网跳板。
- **建议**（按代价从低到高）：
  1. `_check_base_url` 增加主机校验：拒绝 `localhost` / `127.0.0.0/8` / `10.` / `172.16-31.` / `192.168.` /
     `169.254.` / `::1` / `fc00::/7`，除非显式设置 `LLM_ALLOW_PRIVATE=on`；
  2. 解析 DNS 后对**解析结果**再校验一次（防 DNS rebinding 指向内网）；
  3. 请求禁用重定向跟随（`urllib` 默认不跟随 30x 到其他 host，但自定义 opener 时要显式关）；
  4. 探测响应只回状态码与延迟（现状已如此，保持），永不回正文。

### P0-2 `server.py` 已成单体瓶颈，新功能继续往里堆

- **位置**：`src/server.py`（1,722 行，其中 `_settings` 一族约 250 行是本次新增）
- **现象**：路由分发、鉴权、限流、KB 版本、笔记、设置、静态页全在 `create_server()` 的一个
  `Handler` 类里，且依赖 `note_ref`、`pipe`、`store` 等闭包变量。
- **影响**：
  - 任何新接口都要改同一个文件，回归半径 = 整个服务；
  - Handler 无法被单独实例化，**路由层零单元测试**，只能起真实服务打 HTTP；
  - 闭包依赖让「换一个存储位置要重建哪个对象」这类问题只能靠读代码回答（本次已踩过一次）。
- **建议**：
  1. 按资源拆 `src/api/{ask,kb,notes,settings,admin}.py`，每个模块暴露
     `handle(ctx, req) -> Response`，Handler 只做 URL → 模块的路由表；
  2. 把闭包依赖收进一个显式 `AppContext`（字段：`pipe` / `store` / `note_ref` / `guards` / `metrics`），
     构造函数注入，测试里可以塞假对象；
  3. 路由表用字典声明，顺带生成 `/openapi.json`，消除 OpenAPI 与实现两处维护。

### P0-3 本次新增的端到端测试没进 CI，且流水线缺静态门禁

- **位置**：`.github/workflows/ci.yml`
- **现象**：已有 `e2e_pages.mjs`、`e2e_notes.mjs` 两个 Node 步骤，
  但本次新增的 **`tests/e2e_settings.mjs`（36 项）没有加进去**；
  全流程无 `ruff` / `mypy` / `eslint` / 覆盖率统计。
- **影响**：设置抽屉是本次改动的全部交付面，它的端到端验证只在我本机跑过。
  下次任何人改 `theme.py` 或 `server.py` 的设置路由，没有任何自动保护。
- **状态**：`e2e_settings.mjs` 已补进 CI（本次提交）；lint 与覆盖率门槛仍待做。
- **建议**：
  1. 在 Node 步骤里补 `node tests/e2e_settings.mjs`（一行）；
  2. 加 `ruff check src tests tools`（零依赖项目也能用，配置极少）；
  3. 加覆盖率：`coverage run -m ... && coverage report --fail-under=60`，
     先设低门槛拦住「新增代码完全不测」；
  4. Python 版本矩阵只有 3.11/3.13，缺 3.12，补一行即可。

### P0-4 前端存在存储型 XSS 面：文件名未转义就进 `innerHTML`

- **位置**：`src/web_pages.py` 约 1326 行 `renderApprovals()`
  ```js
  var files=(c.files||[]).map(function(f){ return actionText(f.action)+' '+f.name; });
  var dels=(c.deletes||[]).map(function(n){ return '删除 '+n; });
  ```
  同文件 1540 / 1552 / 1704 行把 `g.dataset.name`、`NOTE.cur.title` 直接拼进 `confirm()` 文案。
- **影响**：上传一个名为 `<img src=x onerror=alert(1)>.md` 的文件，审批面板渲染时脚本执行。
  单人自用影响有限；**一旦知识库共享或服务多人可访问，就是持久化 XSS**（载荷存在文件名里，刷新即触发）。
- **建议**：
  1. `f.name` / `n` 一律套 `esc()`（同函数内 `c.warnings` 已经套了，属遗漏而非设计）；
  2. `confirm()` 里的拼接至少去掉引号与换行，避免文案截断误导；
  3. 补一条 E2E：上传恶意文件名 → 断言页面无 `alert` 触发且文件名原样显示；
  4. 中期方案：列表渲染改用 `document.createElement` + `textContent`，从根上消除拼接。

## 三、P1 · 应尽快处理

### P1-1 测试金字塔倒置：全是集成测试，没有单元层

- **位置**：`tests/`（33 个脚本全部起服务或跑完整链路）
- **影响**：单次全量回归以分钟计；失败时定位落在「哪一层」要靠日志；
  `digest_rule`、`chunking`、`select` 这类纯函数逻辑本可以毫秒级验证。
- **建议**：保留现有集成测试作为「回归保障」，为纯函数补 `tests/unit/`，
  用 Python 标准库 `unittest` 即可（不引 pytest，维持零依赖）。
  优先后补：`chunking`（切分边界）、`select`（切片规则）、`guards`（限流窗口）、`appconfig`（校验）。

### P1-2 无静态检查，前端 JS 零校验

- **位置**：CI 无 lint；`theme.py` / `web_pages.py` 里约 3,000 行 JS 全在 Python 字符串中
- **影响**：JS 拼错只有运行时才暴露。本次开发中确实出现过「面板套错层」这类问题，
  靠 E2E 和肉眼发现，不是靠工具。
- **建议**：`ruff check`（Python）+ `node --check`（把内联 JS 抽成临时文件做语法校验，
  一条脚本即可）+ 可选 `eslint`。前端若要长期演进，考虑抽出 `static/app.js`。

### P1-3 `admin_token` 用 `==` 比较，与项目自身规范冲突

- **位置**：`src/server.py:468`、`src/server.py:602`（本次新增）
- **对照**：`src/auth.py` 用了 `hmac.compare_digest`，并注明「避免逐字符比较泄露前缀」
- **影响**：同一项目两套标准；token 比较存在理论上的时序侧信道。风险低（本机 + 有长度校验），
  但**规范不一致比漏洞本身更麻烦**——后人不知道哪套是对的。
- **状态**：已修。新增 `auth.safe_equal()`（先各自 SHA-256 再 `compare_digest`，长度不同也走完整轮），
  `server.py` 两处统一调用，并在 `test_auth_openapi.py` 补了 5 条断言。
- **建议**：抽 `auth.safe_equal(a, b)`，两处统一调用；并把这条写进 `AGENTS.md` 的约定里。

### P1-4 会话、幂等、限流三套状态有两份实现，只在部分路径验证

- **位置**：`src/sessions.py` / `src/guards.py` / `src/redis_client.py`
- **现象**：本地内存实现与 Redis 实现并存，`test_server_redis.py` 覆盖了两个实例共享，
  但设置/笔记相关的新接口没有走这套一致性测试。
- **影响**：多实例部署时，「本机能跑、两台机器行为不同」这类问题会晚发现。
- **建议**：明确文档化「哪些状态必须共享」（会话、幂等键、限流桶、成本计数），
  并为每个状态补一条「双实例」断言；或者干脆声明「本项目只支持单实例」，
  把 Redis 路径标为实验性，降低预期错配。

### P1-5 错误处理：兜底到位，但异常信息被压缩

- **位置**：31 处 `except Exception` + `# noqa: BLE001`
- **现象**：多数回给客户端的是 `服务端异常：{type(exc).__name__}`，原始 message 只进 stderr。
- **影响**：用户看到 `服务端异常：ValueError`，无法自助；排查必须回到服务端日志。
- **建议**：区分「可安全外露」与「不可外露」两类异常：
  前者（校验、路径、配置）把 message 带给客户端；后者（内部实现）保留 type +
  一个短 `error_id`，同时把这个 id 打进日志，用户报 id 即可定位。
  本次 `_settings` 的 500 分支已经带了 message，可作为范本统一。

### P1-6 依赖管理：运行时零依赖做得彻底，但开发依赖没声明

- **位置**：`requirements.txt`（全为注释）、CI 里 `npm install --no-save playwright`
- **影响**：新环境复现「跑 E2E」需要读 CI 文件猜依赖；`--no-save` 意味着版本不锁，
  上游发新版可能导致 E2E 突然失败。
- **建议**：新增 `requirements-dev.txt`（`playwright` 固定版本、`ruff` 固定版本），
  `package.json` 锁 playwright 版本；README 加一节「开发环境」。

## 四、P2 · 可排期优化

### P2-1 性能：三处可优化，但当前量级不构成问题

| 位置 | 现状 | 影响 | 建议 |
|---|---|---|---|
| `appconfig._read()` | 每次 1 次 `stat`，另有 1 秒缓存兜底 | 一次问答约 10 次 `load_settings` → 10 次 stat | 已有缓存，够用；若要更稳可改为「写入时 bump 版本号」 |
| `server._count_notes()` | `rglob("*.md")` 全盘遍历 | 1000 篇约 tens of ms，仅在切换存储时触发 | 可接受；超过 1 万篇再改成读索引行数 |
| `NoteStore.stats()` | 全量 `list()` 后聚合 | 首次会触发索引重建（1000 篇 2.0 s） | `/api/notes/stats` 加「冷启动返回 202 + 后台建索引」 |

> 既有实测：1000 篇笔记保存 P50 12ms / P95 19ms，list 20.9ms，重建 2.0s（4 线程）。
> 这个量级下不需要提前优化。

### P2-2 重复代码：`esc()` 在两处定义

- **位置**：`src/theme.py` 的 `SETTINGS_JS`（IIFE 内）与 `JS_UTIL`（全局）
- **影响**：两份转义规则未来可能漂移，改一处漏一处就会出现 XSS 缺口。
- **状态**：已修。`SETTINGS_JS` 改为 `var esc=window.esc`，直接复用 `JS_UTIL` 那份。
- **建议**：删掉 `SETTINGS_JS` 里的私有 `esc`，直接用全局（加载顺序已保证 JS_UTIL 在前）。

### P2-3 包依赖倒置：`src.notes` 反向依赖 `src.appconfig`

- **位置**：`src/notes/store.py` `from .. import appconfig`
- **影响**：`notes` 本可以独立分发（MCP 场景只需这一个包），现在必须带上整个 `src`。
- **建议**：把「读配置」改成构造参数注入（`NoteStore(home=...)` 已有），
  在 `service`/`cli`/`mcp_server` 入口处读一次配置再传下去。

### P2-4 可维护性：README 1,300+ 行、前端全内联

- **影响**：文档与实现同步成本高（本次改动要同步 5 处文档）；前端改样式必须重启 Python 服务。
- **建议**：README 拆成「快速开始（200 行内）+ docs/ 分册」；
  前端若继续演进，抽出 `static/` 并用构建期注入的方式挂载。

## 六、值得肯定的部分

审查要给出对照，否则容易误判整体质量：

- **外部调用纪律**：`urlopen` 全部带 timeout，重试有退避与抖动，降级路径写进 trace（`degraded` / `degrade_reason`）。
- **上传安全**：显式拒绝路径分隔符而不是静默改名，取舍写进了注释。
- **数据完整性**：笔记写入走「临时文件 + 原子替换」，索引可删可重建，版本库用硬链接做增量。
- **零依赖**：真做到运行时只依赖标准库，xlsx/docx/pdf 都是自己解析的。
- **注释质量**：解释 why 不解释 what，关键取舍有记录（这是最难得的一项）。
- **测试意识**：33 个可执行脚本 + 3 个 E2E，覆盖了大多数失败路径，只是结构偏集成。
