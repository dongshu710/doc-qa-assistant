# 评测说明

评测分三层，各自回答不同问题：

| 层 | 回答的问题 | 是否确定性 | 入口 |
|---|---|---|---|
| L1 断言 | 行为对不对、关键事实在不在、该拒的有没有拒 | 是 | `tests/eval_run.py` |
| L3 语义 | 答案是否忠实于资料、是否切题、是否完整 | 否（裁判模型） | `tests/eval_l3.py` |
| 召回 | 该出现的资料有没有被检索进来 | 是 | `tests/eval_retrieval.py` |

只在 L1 上刷分不够：关键词对了但答案是编的，L1 看不见。只用 L3 也不行：裁判本身不稳定，且看不到检索缺口。
两层一起看，再加召回指标，才能定位「是没检索到，还是检索到了但答错」。

## 1. 数据集

| 集合 | 条数 | 分布 | 用途 |
|---|---|---|---|
| 基础集 `tests/eval_cases.jsonl` | 25 | 正常 12 / 边界 7 / 对抗 6 | 发布门禁 |
| 反馈回归 `tests/eval_cases_feedback.jsonl` | 1 | 差评转用例 | 防止改坏 |
| 难题集 `tests/eval_cases_hard.jsonl` | 13 | 多跳 4 / 数值边界 4 / 跨文件冲突 3 / 资料空白 2 | 诊断，不进门禁 |
| 文档用例 `tests/eval_cases_docs.jsonl` | 运行时生成 | 由上传文档自动出题 | 验证新文档接入 |

对抗集覆盖：提示注入、套取系统提示、越权访问他人信息、荐股/收益承诺、超长输入、无关问题。
资料空白集专门验证「答不出是否转人工」，而不是硬编一个答案。

## 2. 结果（2026-10-18）

### L1 确定性断言

| 轮次 | 用例 | 通过 | 说明 |
|---|---|---|---|
| 离线基线 `baseline.json` | 26 | 26 / 26（100%） | 抽取式，不调模型 |
| glm-5.2 `report_llm_glm.json` | 26 | 26 / 26（100%） | 测试通道 |
| 难题集 `report_hard_glm.json` | 13 | 13 / 13（100%） | 含召回断言 |
| 难题集离线 `report_hard_offline.json` | 13 | 7 / 13（53.8%） | 抽取式兜底的固有短板 |

两类用例分开看：基础集证明「日常问题与安全边界不出错」，难题集证明「多跳、跨文件、数值边界能答对」。
离线模式在难题集上明显下降，是预期行为——它只能摘抄单块资料，做不了跨块归纳。

### L3 语义评分

被测与裁判均为 glm-5.2，14 条答案类 + 12 条拒答类：

| 维度 | 均分 |
|---|---|
| 忠实度 | 5.00 |
| 相关性 | 5.00 |
| 完整性 | 5.00 |

语义通过率 100%，编造告警 0 条，门禁通过。

**校准**（植入错误答案，看裁判是否降分）：

| 校准样本 | 维度 | 得分 | 是否抓到 |
|---|---|---|---|
| 编造数字 | 忠实度 | 1 | ✓ |
| 答非所问 | 相关性 | 1 | ✓ |
| 多问只答一半 | 完整性 | — | 跳过（缺合适基准） |

**异构裁判**（同一批答案，只换裁判模型）：

| 维度 | 同源 glm-5.2 | 异构 deepseek-v4-flash |
|---|---|---|
| 忠实度 | 5.00 | 5.00 |
| 相关性 | 5.00 | 4.92 |
| 完整性 | 5.00 | 4.92 |

结论：存在轻微自偏好，但量级不大（0.08）；更主要的问题是题目偏简单，分数接近天花板。
因此 L3 分数只作趋势对比，门禁取更严的一侧。

### 召回

11 条带召回标签的难题：

| 策略 | Recall@1 | Recall@4 | MRR |
|---|---|---|---|
| bm25 | 72.7% | 90.9% | 0.883 |
| **bm25 + 查询扩展** | **81.8%** | **100%** | **0.909** |
| hybrid | 72.7% | 90.9% | 0.900 |
| hybrid + 查询扩展 | 72.7% | 100% | 0.864 |

结论：

- **查询扩展是真正的增益点**，H10 从漏召回变成第 1 名命中；
- **hybrid 在本语料没有增益**，31 块、术语密集，BM25 已足够强，所以默认仍是 `RETRIEVAL=bm25`；
- 样本量小，结论是方向性的，不作为绝对排名。

## 3. 复现

### 离线（不需要 Key，结果确定）

```bash
python tests/eval_run.py --cases tests/eval_cases.jsonl --out tests/baseline.json
python tests/eval_retrieval.py --out tests/report_retrieval_offline.json
```

### 接模型（需要环境变量）

```bash
export LLM_CHANNEL=glm
export SENSENOVA_API_KEY=<your-key>

python tests/eval_run.py --out tests/report_llm_glm.json
python tests/eval_l3.py --report tests/report_llm_glm.json --out tests/report_l3.json
python tests/eval_retrieval.py --expand --sleep 1 --out tests/report_retrieval.json
```

### 单条 trace 怎么看

每次请求写一行 `logs/trace.jsonl`，包含 query、behavior、mode、latency、retrieval_score、citations、degraded。
看板 `/dashboard` 直接展示最近 20 条；`src/metrics.py` 负责聚合 P50/P95、行为分布、降级率与引用覆盖率。

## 4. 口径与局限

- **L1 通过线**：发布门禁要求基础集 100%。任何一条失败都不应发布。
- **L3 通过线**：忠实度 ≥ 4 且无编造告警；门禁取同源与异构裁判中更严的一侧。
- 用例与知识库自洽，换成真实制度后必须用真实 badcase 重建，不能直接沿用这套分数。
- L3 裁判不确定，单条分数不作绝对判定；当前样本量（26 条）不足以做统计显著性结论。
- 召回评测只有 11 条标签，且由人工标注，存在主观性。
- 评测不覆盖「多轮上下文」——当前产品是单轮问答。
