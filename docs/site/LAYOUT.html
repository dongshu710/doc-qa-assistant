界面与交互方案（v1.19.0）

参照 DeepSeek 网页版的三段式结构重排全部页面：左侧常驻栏 / 中间对话流 / 底部输入。 目标不是「做得像」，而是让第一次打开的人不需要读说明就知道从哪开始、东西存在哪、接口在哪配。

!问答页

三页共用外壳，只有正文不同：

  • /ask：对话页。空态是「问候 + 4 个示例问题」，首条提问后示例让位给对话流。
  • /kb：知识库。标题 + 文档表（勾选、批量删除、状态只标异常）+ 行内「分段」抽屉（先铺 80 条，滚到底再补，正文点开才渲染）；页头「版本 vNNNN」可点，列出全部版本与各自文档；页头还有「检索调试」入口。（v1.29 起笔记分区已并入 /notes，知识库只留只读语料）
  • /notes：笔记页，笔记的唯一完整入口。左列文件（可搜索）、右侧正文与附件；侧栏「笔记」按钮只给最近 5 篇，点任意一条跳到这里。旧地址 /files 301 过来。

三页都有「连接智能体」（#agentBtn）：应用给人用，智能体走 MCP，两条路读的是同一批 Markdown。面板里直接给出可复制的 mcpServers 配置、接出的工具数量和笔记目录， 把「智能体也能读这些笔记」从文档里的一句话变成点得到的按钮。

移动端（≤900px）侧栏变成抽屉：#sideOpen 滑出，点遮罩或按 Esc 收起； 设置与文件抽屉的层级高于侧栏，打开时会自动收起侧栏，不会被挡在后面。

版本清单与分段抽屉

版本清单只读：哪一版当前生效、几份文档、多大、什么时候、怎么来的，点「看文档」展开该版文件名。 整库回退刻意不做——那会连带撤掉后来所有审批过的变更，退单份文档用表格行内的「历史」。

分段抽屉回答的是「这份文档切得好不好」：序号、页码、字数、正文按需展开。它同时是 「这份文档能不能答这个问题」的入口，底部可以直接拿一个真实问题只在这份文档里检索。

三、API 接入的交互流程

配置入口在「设置 → 接口」（输入框里的「离线抽取」标签也直达这里）。

  1. 看结论：顶部状态块先回答「现在能不能用」——未接入 / 已接入某个模型，并说明未接入时走离线抽取。
  2. 填三项：接口地址（填到 /v1 这一层）、模型名、密钥。密钥只写进本机 data/app.json，界面只回显掩码。
  3. 测一次：POST /api/settings/test 真打一次最小请求，成功返回往返毫秒数；401 / 404 / 429 分别给出不同提示，不重试（重试只会让等待翻倍）。
  4. 即时保存：离开输入框（或按 Enter）就写盘并立刻生效，没有保存按钮；

    5. 按 Esc 关面板也会把没提交的改动落下。

失败路径都有明确文案：地址格式不对在保存前就拦；连不上会说明是网络还是超时； 页面上同时给了 DeepSeek 密钥获取地址，避免用户卡在「密钥从哪来」。

四、存储空间：怎么算、怎么改、怎么清

GET /api/settings 新增 storage 字段，全部是磁盘真实字节，不做「每篇约多少 KB」的估算：

{
  "notes":  { "bytes": 1153433, "files": 2, "path": "C:\\Users\\…\\agent-notes\\notes" },
  "index":  { "bytes": 1024, "path": "…\\agent-notes\\index" },
  "kb":     { "bytes": 94266982, "versions": 9, "path": "…\\data\\kb" },
  "config": { "bytes": 512, "path": "…\\data\\app.json" },
  "embedding": { "bytes": 0 },
  "disk":   { "total": 214748364800, "free": 111669149696, "root": "C:\\" },
  "keep_versions": 30
}

界面上的堆叠条按 知识库 / 笔记 / 索引缓存 三段显示占比，右侧给「磁盘剩余 / 总容量」。 这样用户能直接判断是该清版本，还是该换盘。

保留策略：storage.keep_versions（默认 30，0 表示不清理）写入 data/app.json， 同时映射到环境变量 KB_KEEP_VERSIONS。活动版本与待审批变更的基线版本永不删除， 否则回滚和审批会直接失败。

一键清理（POST /api/settings/storage/clean）：

  1. 按所选保留数删旧版本；
  2. 删笔记索引缓存（只是缓存，下次读取自动重建）；
  3. 返回删掉的版本号、释放字节数与清理后的占用。

不在这里重建索引：重建会立刻把刚删的缓存写回来，用户看到「释放 0 B」会以为按钮坏了。

换位置沿用既有能力：默认位置 / 自定义目录、原生目录选择器、迁移旧笔记。 换目录不会自动搬文件，只在原位置还有笔记时提示一次「要复制过来吗」。

五、开源项目拆解与本项目的取舍

项目值得吸收的点本项目是否采用
DeepSeek 网页版左栏 + 单列对话 + 大圆角输入框；空态用示例问题代替功能说明采用，作为整体骨架
LibreChat会话搜索、模型选择前置到输入区、右侧上下文面板采用搜索与会话切换；不做右侧面板——本项目的引用原文用抽屉按需打开，常驻会挤压正文
Open WebUI「文件夹即工作区」：文件夹可绑定 system prompt 与知识库部分采用：知识库本身就是全局工作区，没有再引入文件夹层级，避免多一层心智负担
LobeChat设置左导航 + 右内容的弹窗结构、克制的动效采用设置弹窗结构；动效只保留 0.15–0.2s 的透明度/位移
AnythingLLM存储占用可视化、按文档量估算容量采用可视化；不采用估算值，改为真实字节

刻意没做的：

  • 不做多模型并排对比：当前后端一次请求只走一个模型，做出来就是假开关。
  • 不做文件夹分组：会话是临时的，真要沉淀走「存为笔记」，两条路径不混。
  • 不做账号头像：单机使用没有账号，用版本号 + 主题切换占位更诚实。

七点五、首次运行与存储区（v1.19.0）

为什么要有这一步：内容一旦落在浏览器里，换设备就等于丢；而「存在哪」又决定了 能不能整目录备份、智能体读不读得到。所以第一次打开只做一件事——把存储区定下来。

第一次打开
   └─ 弹窗：给文档安个家
        ├─ 默认路径：~/记忆文档（老用户已有笔记时，默认给他在用的那个目录）
        ├─ [选择…] 调系统目录选择框
        └─ [建在这里] → notes/ threads/ index/ exports/ assets/ 全部建好，写 setup.done

弹窗里只讲三句实话：文档是 Markdown、会话是 JSON、智能体读同一个目录。

存储面板：四个数字就够

存储区   /Users/me/记忆文档                 [打开目录] [更换]
笔记（Markdown）、会话（JSON）、导出都在这一个目录里。整个目录拷走就是完整备份。
┌ 文档 ─────┐ ┌ 会话 ─────┐ ┌ 缓存 ─────┐ ┌ 磁盘剩余 ──┐
│ 128 KB    │ │ 36 KB     │ │ 2.2 KB    │ │ 105 GB     │
│ · 12 篇   │ │ · 3 条    │ │           │ │            │
└───────────┘ └───────────┘ └───────────┘ └────────────┘
保留知识库旧版本 [最近 30 版]        [清理缓存与旧版本]

旧的「面积条 + 五段图例」被删掉了：用户要的是「多大、还剩多少」， 不是先学一套颜色再换算比例。路径只在顶部出现一次，点「更换」才展开输入框。

笔记页：能改才算自己的

每条笔记右上角两个动作：编辑原文（行内 textarea，保存带 base_rev 乐观锁）、 用系统编辑器打开（POST /api/files/open）。改的是磁盘上的真文件， 所以编辑框上方会提醒一句：删掉 front matter 也能用，但标签、状态这些字段会丢。

八、已知取舍

  • 会话记录存在浏览器 localStorage（最多 60 条），换浏览器就看不到；要长期保留请「存为笔记」。
  • 存储统计仍然要遍历目录：os.scandir + 五个目录并行后，1000 篇约 5 ms（原 20 ms）；

    • 30 秒内重复打开走缓存，约 0.05 ms。缓存按「索引文件 + 各根目录的 mtime/size」验指纹， 存一篇笔记就立刻失效；只有「用别的编辑器往目录里丢文件」这种绕过索引的动作最多滞后 30 秒。

  • 前端资源已搬到 src/web/，但仍然是内联进 HTML（不新增静态路由、不引入构建步骤），

    • 所以改完样式或脚本要重启进程；tools/check_frontend.py 负责在提交前抓语法错误。

  • 清理按钮按当前选择执行，没有二次确认——删的是旧版本与缓存，活动版本永不受影响；

    • 但如果用户依赖某个旧版本回滚，删掉后就没了，这一点在面板文案里写明。
