智能体笔记工具 · 改造规划（v2.0 方向）

状态：方案待确认（Phase 0–1 交付），尚未改动代码。 结论先行：把现有「五页 RAG 演示站」收成「两页 + 一个智能体可调用的个人笔记存储」。 存储以 Markdown 文件为唯一真相，索引可删可重建；摘要走「规则引擎保底 + 大模型增强」双引擎； 接入走「MCP 主通道 + HTTP 兼容 + CLI 兜底 + 文件直读」四级阶梯。

1. 目标与边界（五要素）

项内容
目标让任意智能体在对话中挑选有价值的内容，整理成结构化笔记，落到用户自己的目录；人能离线翻、随手改；同一份内容可被下一个智能体读到
输入智能体传来的消息数组（含 role/text），可带选中范围、标题、标签、类型提示；也接受人工在页面上勾选
输出一个 Markdown 文件（front matter + 六段正文）+ 一条索引记录 + 一个稳定 note_id
成功指标① 无大模型时 100% 能产出合法笔记；② 保存 P95 < 300ms（1k 字）；③ 索引删除后可 100% 重建；④ 人工改文件后读取立即生效（自愈率 100%）；⑤ ≥ 5 种智能体可按文档接入
约束零第三方依赖（标准库）；全中文；单机优先、数据不出本机（除显式开启的大模型摘要）；不破坏现有问答与文档上传能力

不做什么：不做云端同步、不做多租户、不做向量化笔记库（先留接口）、不做自动抓取对话（必须显式调用/勾选）。

2. 先回答：这需要 Agent 吗？

不需要，而且不该做成 Agent。

这是给智能体用的工具 + 记忆层：无自主循环、无规划器、无工具编排。真正的 Agent 在调用方（Claude/Cursor/自研），本项目的职责是把「一次工具调用」做对：幂等、可预览、可撤销、格式稳定。

由此定下三条设计红线：

  1. 不引入自主循环 —— 本项目没有 while True，不需要 max_steps；但必须给调用方提供幂等键与预算上限（单次摘要 token 上限），防止调用方重试把成本放大。
  2. 写操作要能预览 —— draft 先返回渲染结果与目标路径，commit 才落盘；删除是 L2，必须带 confirm_token。
  3. 格式即契约 —— 文件格式一旦发布就要向后兼容，所有接口都是它的皮。

关键取舍：

  • 文件是真相，索引是缓存。索引删了不丢数据；外部编辑以文件为准，索引只跟随不覆盖。
  • 三个入口一套用例。MCP/HTTP/CLI 只做协议转换，全部调 NoteService，避免三套行为漂移。
  • 摘要是可插拔的。DIGEST=rule 时零依赖零成本；auto 时有 Key 走模型、失败即降级。

4.1 目录

NOTE_HOME（默认 ~/agent-notes，可用环境变量或 --home 覆盖）

6. 第一步：只做一件事（P0 竖切片）

把「一段对话 → 一个合法 Markdown 文件 → 读回来 → 手改后仍读得对」跑通，全程不接大模型。

范围（只含 M1 + M2 最小集 + M3 的 RuleDigest + 一个 notes CLI）：

src/notes/__init__.py
src/notes/model.py       # Note 数据类、校验、序列化/反序列化
src/notes/store.py       # 路径、原子写、锁、软删除、扫盘
src/notes/index.py       # notes.jsonl 生成 / 重建 / 增量刷新
src/notes/select.py      # 消息切片、去重 hash、幂等表
src/notes/digest_rule.py # 规则摘要（标题/要点/决策/待办/引用）
src/notes/cli.py         # save / list / get / rebuild / export
tests/test_notes_store.py
tests/test_notes_digest_rule.py

CLI 接口（先定形，后续 HTTP/MCP 复用同一参数语义）：

notes save --from conv.json --kind decision --tags 税务,出口退税 [--draft] [--keep-raw]
notes list --tag 税务 --since 2026-10-01 --limit 20 --json
notes get <id> [--json]
notes rebuild

验收标准（可执行，缺一不算完成）

  1. notes save --from conv.json 生成 notes/2026/10/<id>.md，front matter 六字段齐全，正文含「摘要 + 要点」两节。
  2. 手工把标题改成「改过的标题」→ notes get <id> --json 返回新标题（自愈）。
  3. rm -rf index/ → 下次 notes list 自动重建，条数与磁盘 .md 数一致。
  4. 同样的 conv.json 保存两次 → 第二次返回 duplicate_of=<id>，不产生新文件。
  5. 把 front matter 删掉再读 → 不报错，external: true，标题取文件名/首行。
  6. 1k 字笔记：save P95 < 300ms、list(1000 篇) < 100ms、零第三方依赖。

为什么先做这个：文件格式是唯一会被用户长期持有、被多个智能体共同读写的东西，改一次就要迁移全部数据；接口层（HTTP/MCP）都是薄壳，晚做一天不影响正确性，格式做错一天要还债一年。

7. 工具面设计（M4 预定稿）

工具级别输入要点行为
save_conversationL1 可撤销写messages[]、select、hint、mode=draft/commit、idempotency_key草稿只渲染不落盘；commit 写文件并返回 id/path/preview
preview_noteL0 只读同 save_conversation，强制 draft返回 markdown 预览与目标路径
search_notesL0query、tags[]、since/until、limit≤50返回 id/title/summary/tags/updated
get_noteL0id、section?返回正文，超 6000 字截断并标 truncated
append_to_noteL1id、markdown、section追加到指定小节，不重写其他内容
update_noteL1id、base_hash、patch乐观锁，hash 不符返回 409 conflict
delete_noteL2id、confirm_token移入 .trash，可 restore

resources：note://{id}（单篇全文）、notes://recent（最近 20 条摘要）——让智能体不调工具也能读。

错误码统一：invalid_argument / not_found / conflict / duplicate / unavailable / confirm_required，全部带 message 与可执行建议；不向上抛异常栈。

8. 摘要双引擎与降级矩阵

场景引擎输出标记
无 Key / DIGEST=ruleRuleDigest（分句打分 + 关键词段落归类）六段中至少摘要 + 要点digest: rule
有 Key / DIGEST=auto 或 llmLlmDigest（JSON 输出 + 强校验）六段齐全digest: llm
模型超时 / 非 200 / JSON 坏 / 字段非法先重试 2 次（指数退避 + 抖动），仍失败 → RuleDigest与规则同digest: llm-fallback + degrade_reason
输入超长先按 token 预算截断（保留首尾）标 truncateddigest: *

硬性要求：RuleDigest 永不抛异常，任何输入都要产出可用笔记——这是"不依赖大模型也能完成基本功能"的兜底。

9. 多智能体适配矩阵

智能体接入方式说明
Claude Desktop / Claude CodeMCP stdio配置里填启动命令与 NOTE_HOME
Cursor / Windsurf / ClineMCP stdio同上，一套配置通用
ChatGPT（Actions）/ Dify / CozeOpenAPI HTTP读 /openapi.json，需可达地址（本机需隧道）
LangChain / LlamaIndex / 自研HTTP 或 tools.json直接拿 function schema
只给执行命令的智能体CLI --json兜底通道，任何环境可用
完全离线直接读 Markdown无服务、无依赖、无 Key

四层阶梯的意义：文件是通用货币，MCP 是主通道，HTTP 是广谱适配，CLI 是兜底。任何一个通道坏掉，其余仍可用。

风险概率影响应对

#议题决定理由
1存储位置默认 ~/agent-notes，NOTE_HOME 或 --home 覆盖「个人储存空间」要跨项目、跨智能体复用；放项目里换个目录就丢
