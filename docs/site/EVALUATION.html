评测说明

评测分三层，各自回答不同问题：

层回答的问题是否确定性入口
L1 断言行为对不对、关键事实在不在、该拒的有没有拒是tests/eval_run.py
L3 语义答案是否忠实于资料、是否切题、是否完整否（裁判模型）tests/eval_l3.py
召回该出现的资料有没有被检索进来是tests/eval_retrieval.py

只在 L1 上刷分不够：关键词对了但答案是编的，L1 看不见。只用 L3 也不行：裁判本身不稳定，且看不到检索缺口。 两层一起看，再加召回指标，才能定位「是没检索到，还是检索到了但答错」。

1. 数据集

2. 结果（2026-10-18）

L1 确定性断言

轮次用例通过说明
离线基线 baseline.json2626 / 26（100%）抽取式，不调模型
接入模型 report_llm.json2626 / 26（100%）评测者自备模型
难题集 report_hard.json1313 / 13（100%）含召回断言
难题集离线 report_hard_offline.json137 / 13（53.8%）抽取式兜底的固有短板

两类用例分开看：基础集证明「日常问题与安全边界不出错」，难题集证明「多跳、跨文件、数值边界能答对」。 离线模式在难题集上明显下降，是预期行为——它只能摘抄单块资料，做不了跨块归纳。

被测与裁判为同一模型（model-a），14 条答案类 + 12 条拒答类：

完整性5.00

语义通过率 100%，编造告警 0 条，门禁通过。

编造数字忠实度1✓

异构裁判（同一批答案，只换裁判模型）：

维度同源裁判（model-a）异构裁判（model-b）
忠实度5.005.00
相关性5.004.92
完整性5.004.92

结论：存在轻微自偏好，但量级不大（0.08）；更主要的问题是题目偏简单，分数接近天花板。 因此 L3 分数只作趋势对比，门禁取更严的一侧。

召回

11 条带召回标签的难题：

策略Recall@1Recall@4MRR
bm2572.7%90.9%0.883
bm25 + 查询扩展81.8%100%0.909
vector（默认）72.7%90.9%0.883
hybrid72.7%90.9%0.900
hybrid + 查询扩展72.7%100%0.864

结论：

  • 默认仍是 vector（字符 n-gram 向量 + 重排）；在本语料上 R@1 / R@4 与 BM25 持平，没有虚构增益，换来的是可替换的向量接口与重排链路；
  • 真 embedding 用 python tests/eval_retrieval.py --embedding 评测（需先配置 EMBEDDING_* 并构建索引）。本仓库没有 embedding 凭据，因此没有把未实测的增益写进结果表；
  • 查询扩展是当前有效的召回增益，H10 从漏召回变成第 1 名命中；
  • Hybrid 在本语料没有额外收益，保留为历史对照；
  • 样本量小，结论是方向性的，不作为绝对排名。

3. 复现

离线（不需要 Key，结果确定）

python tests/eval_run.py --cases tests/eval_cases.jsonl --out tests/baseline.json
python tests/eval_retrieval.py --out tests/report_retrieval_offline.json

接模型（需要环境变量）

export LLM_BASE_URL=https://api.deepseek.com/v1
export LLM_MODEL=deepseek-chat
export LLM_API_KEY=<your-key>

python tests/eval_run.py --out tests/report_llm.json
python tests/eval_l3.py --report tests/report_llm.json --out tests/report_l3.json
python tests/eval_retrieval.py --expand --sleep 1 --out tests/report_retrieval.json

单条 trace 怎么看

每次请求写一行 logs/trace.jsonl，包含 query、behavior、mode、latency、retrieval_score、citations、degraded。 数据中心 /insights#p-trace 直接展示最近 20 条；src/metrics.py 负责聚合 P50/P95、行为分布、降级率与引用覆盖率。

4. 口径与局限

  • L1 通过线：发布门禁要求基础集 100%。任何一条失败都不应发布。
  • L3 通过线：忠实度 ≥ 4 且无编造告警；门禁取同源与异构裁判中更严的一侧。
  • 用例与知识库自洽，换成真实制度后必须用真实 badcase 重建，不能直接沿用这套分数。
  • L3 裁判不确定，单条分数不作绝对判定；当前样本量（26 条）不足以做统计显著性结论。
  • 召回评测只有 11 条标签，且由人工标注，存在主观性。
  • 评测不覆盖「多轮上下文」——当前产品是单轮问答。
