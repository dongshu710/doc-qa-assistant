# 界面与交互方案（v1.19.0）

参照 DeepSeek 网页版的三段式结构重排全部页面：**左侧常驻栏 / 中间对话流 / 底部输入**。
目标不是「做得像」，而是让第一次打开的人不需要读说明就知道从哪开始、东西存在哪、接口在哪配。

![问答页](screenshots/ask.png)

## 一、结构对照

| DeepSeek 的区域 | 本项目对应 | 说明 |
|---|---|---|
| 左上角 Logo | 品牌区（`#sideBar .brand`） | 点回问答页 |
| 「开启新对话」 | `#newChat` | 同时把服务端会话 ID 换新，避免新对话里模型还记得上一段 |
| 历史对话列表 | `#convList` | 按 今天 / 昨天 / 7 天内 / 更早 分组；标题取第一个问题前 28 字 |
| 历史搜索 | `#convSearch` | 本地过滤标题，不发请求 |
| 左下账号 / 设置 | 文件 / 知识库 / 设置 三行 | 本项目没有账号体系，这一栏放的是「东西在哪」与「配置在哪」 |
| 中间对话区 | `#list` + `#hero` | 有消息时显示对话流，没有时居中显示问候与示例问题 |
| 底部输入框 | `#composer` | 大圆角浮层，工具项收在框内底部一行 |
| 深度思考 / 联网搜索开关 | 知识库 / 接口 两个状态标签 | 只放**真实存在**的能力：知识库版本、当前模型或离线抽取；不做无后端支撑的开关 |
| 右上头像 / 设置 | 导出 / 清空 | 与当前会话相关，不跨页 |

## 二、页面模块与层级

```
<div class="app">
  <aside class="side">            常驻 260px，可收起到 64px
    品牌 / 收起按钮
    新对话（Ctrl+K）
    搜索对话
    会话列表（按时间分组）
    文件（抽屉，带篇数角标与备份红点）
    智能体（实体按钮：状态 + 可复制的 MCP 配置）
    知识库
    设置
    版本号 / 主题切换
  </aside>
  <div class="main">
    页面标题栏（问答页独有：标题、轮次数、导出、清空）
    页面正文
  </div>
</div>
```

三页共用外壳，只有正文不同：

- `/ask`：对话页。空态是「问候 + 4 个示例问题」，首条提问后示例让位给对话流。
- `/kb`：知识库。标题 + 文档 / 笔记两个分区；表格列宽按内容重排，隐藏「关键词」列。
- `/files`：文件页。左列文件、右侧正文，作为加不进客户端工具栏时的固定地址。

三页都有「连接智能体」（`#agentBtn`）：应用给人用，智能体走 MCP，两条路读的是同一批
Markdown。面板里直接给出可复制的 `mcpServers` 配置、接出的工具数量和笔记目录，
把「智能体也能读这些笔记」从文档里的一句话变成点得到的按钮。

移动端（≤900px）侧栏变成抽屉：`#sideOpen` 滑出，点遮罩或按 `Esc` 收起；
设置与文件抽屉的层级高于侧栏，打开时会自动收起侧栏，不会被挡在后面。

## 三、API 接入的交互流程

配置入口在「设置 → 接口」（输入框里的「离线抽取」标签也直达这里）。

1. **看结论**：顶部状态块先回答「现在能不能用」——未接入 / 已接入某个模型，并说明未接入时走离线抽取。
2. **填三项**：接口地址（填到 `/v1` 这一层）、模型名、密钥。密钥只写进本机 `data/app.json`，界面只回显掩码。
3. **测一次**：`POST /api/settings/test` 真打一次最小请求，成功返回往返毫秒数；401 / 404 / 429 分别给出不同提示，不重试（重试只会让等待翻倍）。
4. **保存并启用**：写盘后立刻生效，下一次提问就用新配置。

失败路径都有明确文案：地址格式不对在保存前就拦；连不上会说明是网络还是超时；
页面上同时给了 DeepSeek 密钥获取地址，避免用户卡在「密钥从哪来」。

## 四、存储空间：怎么算、怎么改、怎么清

`GET /api/settings` 新增 `storage` 字段，全部是磁盘真实字节，不做「每篇约多少 KB」的估算：

```json
{
  "notes":  { "bytes": 1153433, "files": 2, "path": "C:\\Users\\…\\agent-notes\\notes" },
  "index":  { "bytes": 1024, "path": "…\\agent-notes\\index" },
  "kb":     { "bytes": 94266982, "versions": 9, "path": "…\\data\\kb" },
  "config": { "bytes": 512, "path": "…\\data\\app.json" },
  "embedding": { "bytes": 0 },
  "disk":   { "total": 214748364800, "free": 111669149696, "root": "C:\\" },
  "keep_versions": 30
}
```

界面上的堆叠条按 `知识库 / 笔记 / 索引缓存` 三段显示占比，右侧给「磁盘剩余 / 总容量」。
这样用户能直接判断是该清版本，还是该换盘。

**保留策略**：`storage.keep_versions`（默认 30，`0` 表示不清理）写入 `data/app.json`，
同时映射到环境变量 `KB_KEEP_VERSIONS`。活动版本与待审批变更的基线版本**永不删除**，
否则回滚和审批会直接失败。

**一键清理**（`POST /api/settings/storage/clean`）：

1. 按所选保留数删旧版本；
2. 删笔记索引缓存（只是缓存，下次读取自动重建）；
3. 返回删掉的版本号、释放字节数与清理后的占用。

不在这里重建索引：重建会立刻把刚删的缓存写回来，用户看到「释放 0 B」会以为按钮坏了。

**换位置**沿用既有能力：默认位置 / 自定义目录、原生目录选择器、迁移旧笔记。
换目录不会自动搬文件，只在原位置还有笔记时提示一次「要复制过来吗」。

## 五、开源项目拆解与本项目的取舍

| 项目 | 值得吸收的点 | 本项目是否采用 |
|---|---|---|
| DeepSeek 网页版 | 左栏 + 单列对话 + 大圆角输入框；空态用示例问题代替功能说明 | **采用**，作为整体骨架 |
| LibreChat | 会话搜索、模型选择前置到输入区、右侧上下文面板 | 采用搜索与会话切换；**不做**右侧面板——本项目的引用原文用抽屉按需打开，常驻会挤压正文 |
| Open WebUI | 「文件夹即工作区」：文件夹可绑定 system prompt 与知识库 | **部分采用**：知识库本身就是全局工作区，没有再引入文件夹层级，避免多一层心智负担 |
| LobeChat | 设置左导航 + 右内容的弹窗结构、克制的动效 | 采用设置弹窗结构；动效只保留 0.15–0.2s 的透明度/位移 |
| AnythingLLM | 存储占用可视化、按文档量估算容量 | 采用可视化；**不采用**估算值，改为真实字节 |

刻意没做的：

- **不做多模型并排对比**：当前后端一次请求只走一个模型，做出来就是假开关。
- **不做文件夹分组**：会话是临时的，真要沉淀走「存为笔记」，两条路径不混。
- **不做账号头像**：单机使用没有账号，用版本号 + 主题切换占位更诚实。

`e2e_layout` 覆盖的关键行为：收起后能再展开、刷新后不重复建会话、切回旧会话正文还在、
搜索能过滤、删除后数量正确、设置是居中弹窗、存储数字有值、清理给出结果、移动端抽屉可开可关。

## 七点五、首次运行与存储区（v1.19.0）

**为什么要有这一步**：内容一旦落在浏览器里，换设备就等于丢；而「存在哪」又决定了
能不能整目录备份、智能体读不读得到。所以第一次打开只做一件事——把存储区定下来。

```
第一次打开
   └─ 弹窗：给文档安个家
        ├─ 默认路径：~/记忆文档（老用户已有笔记时，默认给他在用的那个目录）
        ├─ [选择…] 调系统目录选择框
        └─ [建在这里] → notes/ threads/ index/ exports/ assets/ 全部建好，写 setup.done
```

弹窗里只讲三句实话：文档是 Markdown、会话是 JSON、智能体读同一个目录。

### 存储面板：四个数字就够

```
存储区   /Users/me/记忆文档                 [打开目录] [更换]
笔记（Markdown）、会话（JSON）、导出都在这一个目录里。整个目录拷走就是完整备份。
┌ 文档 ─────┐ ┌ 会话 ─────┐ ┌ 缓存 ─────┐ ┌ 磁盘剩余 ──┐
│ 128 KB    │ │ 36 KB     │ │ 2.2 KB    │ │ 105 GB     │
│ · 12 篇   │ │ · 3 条    │ │           │ │            │
└───────────┘ └───────────┘ └───────────┘ └────────────┘
保留知识库旧版本 [最近 30 版]        [清理缓存与旧版本]
```

旧的「面积条 + 五段图例」被删掉了：用户要的是「多大、还剩多少」，
不是先学一套颜色再换算比例。路径只在顶部出现一次，点「更换」才展开输入框。

### 文件页：能改才算自己的

每条笔记右上角两个动作：**编辑原文**（行内 textarea，保存带 `base_rev` 乐观锁）、
**用系统编辑器打开**（`POST /api/files/open`）。改的是磁盘上的真文件，
所以编辑框上方会提醒一句：删掉 front matter 也能用，但标签、状态这些字段会丢。

## 八、已知取舍

- 会话记录存在浏览器 `localStorage`（最多 60 条），换浏览器就看不到；要长期保留请「存为笔记」。
- 存储统计仍然要遍历目录：`os.scandir` + 五个目录并行后，1000 篇约 5 ms（原 20 ms）；
  30 秒内重复打开走缓存，约 0.05 ms。缓存按「索引文件 + 各根目录的 mtime/size」验指纹，
  存一篇笔记就立刻失效；只有「用别的编辑器往目录里丢文件」这种绕过索引的动作最多滞后 30 秒。
- 前端资源已搬到 `src/web/`，但仍然是内联进 HTML（不新增静态路由、不引入构建步骤），
  所以改完样式或脚本要重启进程；`tools/check_frontend.py` 负责在提交前抓语法错误。
- 清理按钮按当前选择执行，没有二次确认——删的是旧版本与缓存，活动版本永不受影响；
  但如果用户依赖某个旧版本回滚，删掉后就没了，这一点在面板文案里写明。
