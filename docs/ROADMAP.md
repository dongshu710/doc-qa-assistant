# 改进路线（按优先级排序）

排序原则：**先修「用户碰得到、改动小」的，再做「结构性、需要单独回归窗口」的，最后才是能力扩展。**
每一行都能对应到 `docs/AUDIT.md` 的编号或 `docs/PLUGIN.md` 的结论，避免路线图变成许愿池。

工作量口径：S ≈ 半天内，M ≈ 1–2 天，L ≈ 需要单独开一轮并逐族回归。

## P0 · 现在做（低风险，收益立刻可见）

| # | 事项 | 问题 | 做法 | 预期效果 | 量 |
|---|---|---|---|---|---|
| 1 | 「已存」列表键盘可达 | 列表项是 `div`，无 `tabindex`/`role`，键盘与读屏都打不开笔记（实测 `{"tag":"DIV","tabindex":null,"role":null}`） | 加 `role="button"` + `tabindex="0"` + Enter/Space 处理 + `:focus-visible` 样式；e2e 断言 Tab 能聚焦并展开 | 设置抽屉里最后一个只能用鼠标的入口消失 | S |
| 2 | 前端出仓 + 语法门禁（A-2） | 139 KB HTML/CSS/JS 内联在 Python 字符串里，153 个函数，CI 没有 `node --check`；拼错只能等浏览器报错 | 抽到 `src/web/{ask,kb,theme}.{css,js}`，启动时读入（仍零依赖），构建脚本打进 zip；CI 加 `node --check` | JS 错误在提交前暴露；改样式不用再改 Python 转义 | M |
| 3 | 参数边界与常量小修 | `limit=-5` 返回 200 空列表；`HTTPS://…` 被当作非法地址；`/api/settings` 每次都读 `.git/config` | 负数直接 400；协议匹配忽略大小写；`_repo_url()` 按 mtime 缓存 | 错误立刻可见，少一次磁盘读 | S |

## P1 · 下一轮（结构性与「插件」闭环）

| # | 事项 | 问题 | 做法 | 预期效果 | 量 |
|---|---|---|---|---|---|
| 4 | 可安装发行（P-1） | 没有 `pyproject.toml`，插件必须带整个源码目录 + 手写 `PYTHONPATH`，无法 `pip install` | 加 `pyproject.toml`（`requires-python>=3.11`，零依赖），暴露 `agent-notes-mcp = src.notes.mcp_server:main`；文档给 `pipx install .` / `uvx` 两种方式 | 插件从「解压一个仓库」变成「装一个命令」 | M |

## P2 · 质量与可靠性（随模块改动顺手做）

| # | 事项 | 问题 | 做法 | 预期效果 | 量 |
|---|---|---|---|---|---|
| 8 | 计时统一用单调钟（B-1） | 12 处 `time.time()` 用于 TTL/限流/墙钟预算，系统对时会漂 | 间隔、超时、过期全部改 `monotonic()`，墙钟只用于展示 | 改系统时间不再影响会话过期与限流窗口 | S |

| 11 | 超长函数拆分（C-1） | `report.py:render` 361 行、`openapi.build_spec` 280 行 | 拆成「字段表 + 渲染」，字段表可直接断言 | 改报表/OpenAPI 不必读完整函数 | M |

## 不建议做（已实测，收益为负或为零）

| 项 | 实测 | 结论 |
|---|---|---|
| 页面拆包 / 预渲染 | `/ask` 94 KB，gzip 26 KB，TTFB 3–22 ms | 个人本地使用，没有网络瓶颈 |
| 笔记计数缓存 | `rglob` 1,000 篇 2.9 ms | 加缓存只会增加失效逻辑 |
| 多实例 Redis 一致性 | 明确单机单实例 | 维护成本 > 收益 |
| 拒绝私网地址（上轮 P0-1） | 会把 ollama 的 `127.0.0.1:11434` 一起拒掉 | 已在 §1.5 撤销 |

## 建议排期

```
P0（1–2 天）  →  发 v1.13.2（a11y + 前端出仓 + 参数小修）
P1（下一轮）  →  4 → 5 → 6 → 7，每项单独提交、单独回归     ✅ 1.21–1.23 全部完成
P2            →  跟着 5/6 的模块改动顺手做，不单独开轮      ✅ 1.23.0 完成
P3            →  12 / 13 已作为两个独立版本完成（1.25 / 1.26），14 定论不做
```

判断标准：**P0 做完，用户能感知到「更好用」；P1 做完，插件才算真正可分发。**
其余项目在个人单机场景下，都不值得打断当前节奏。
