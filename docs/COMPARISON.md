# 相似开源项目拆解与借鉴清单

> 目的：不靠「再抄一个 DeepSeek 界面」来决定长什么样，而是看同类产品**各自解决了什么**，
> 只借能解决本项目问题的部分。每条都写清「借什么 / 不借什么 / 为什么」。
>
> 事实口径：项目定位与能力取自各项目官方仓库与文档（2026-10 查阅）；
> 具体版本号、Star 数、界面上某个按钮的位置这类会随版本变的信息，一律不写成断言，
> 需要时标 `[待核实]`。

## 一、选这几家的理由

本项目定位：**可接入不同智能体的文档记忆管理应用**。它同时踩在三个圈里——
文档问答（RAG）、个人知识库（PKM）、智能体的记忆层（Agent Memory）。
所以样本从这三个圈各取两个，外加固化成「文件即数据」的两个参照。

| 项目 | 圈层 | 一句话 |
|---|---|---|
| **AnythingLLM** | 文档问答 | 多工作区 + 文档入库 + 向量库，面向「把资料变成可对话的知识」 |
| **RAGFlow** | 文档问答 | 强调「深度文档理解」，把切分与召回过程可视化 |
| **Reor** | 个人知识库 | 本地 Markdown 笔记 + 本地向量库 + 自动关联与问答 |
| **Khoj** | 个人知识库 | 个人 AI：在你自己的文件上做语义检索与对话，可自托管 |
| **Mem0** | 智能体记忆 | 给智能体用的记忆层：写入 / 检索 / 按用户与会话隔离 |
| **Logseq / Obsidian** | 文件即数据 | 笔记就是磁盘上的 Markdown，工具只是它的一个视图 |

---

## 二、逐个拆：借什么，不借什么

### 1. AnythingLLM —— 工作区（workspace）是最好的隔离单位

**它做对了什么**
- 把「一批文档 + 一段对话」打包成**工作区**，切工作区等于换一套资料与上下文；
- 文档入库、向量化、检索、对话是一条龙，用户不需要知道 RAG 的每个零件；
- 桌面端与自托管同一套界面，降低了「本地跑」的门槛。

**借什么**
- **「一次对话绑定一个资料范围」**：本项目已有知识库版本，但问答页只显示一个 `知识库 v0009` 标签。
  下一步可以让会话记住「当时用的是哪一版知识库」，导出与复现时有据可查。
- **入库即完成**：用户不该被迫理解 chunk、embedding。本项目的上传框已经做到「拖进去就能问」，
  但失败提示仍偏工程化，可以再降一层。

**不借什么**
- **多工作区切换器**：本项目是单人单机、一个知识库，加一层「工作区」只会让「东西存在哪」更难回答。
  我们用的是**一个存储区 + 两个区（文档 / 笔记）**，比工作区更贴近「记忆」这个隐喻。

---

### 2. RAGFlow —— 把「切分」摊开给用户看

**它做对了什么**
- 强调文档理解：版面、表格、标题层级都参与切分，而不是按字数硬切；
- 把 chunk 的可视化与召回结果放在同一个界面里，用户能判断「为什么答错了」。

**借什么**
- **可解释的引用**：本项目的答案已经带引用与「检索依据」折叠区，方向一致。
  可以补的是「命中片段在原文里的位置」——引用行点开时，除了段落文本，再给出它在文件中的标题路径。
- **失败可诊断**：没答出来时，RAGFlow 让用户看到「检索到了但没用」还是「根本没检索到」。
  本项目 `behavior=no_answer` 已有区分，界面上可以更直白地说出是哪一种。

**不借什么**
- **一套独立的「知识库工程控制台」**：那是给 RAG 工程师调参用的。我们的用户要的是「记住并找回」，
  不是调 top-k。参数留在配置文件里，界面只留结论。

---

### 3. Reor —— 最接近本项目的一家，两个设计直接采纳

**它做对了什么**（官方仓库与文档口径）
- **首次启动让你选一个目录**，所有笔记就是那个目录里的 Markdown 文件；换目录等于换库；
- 本地向量库 + 自动关联：写着写着侧栏会浮出「语义相关的旧笔记」；
- 官方那句定位很准：*"a RAG app with two generators: the LLM and the human"*——
  人写的时候 AI 找相关，人问的时候 AI 用人写过的东西回答。

**借什么**（已落地）
- **首启建存储区**：本项目 v1.19.0 加了「先给文档安个家」，选目录、自动建 `notes/ threads/ index/`，
  并明确「目录不存在会自动创建、整个目录拷走就是完整备份」。
- **文件即数据**：笔记是 Markdown、会话是 JSON，页面上能直接改原文，也能交给系统编辑器打开。
- **双向生成**（部分落地）：问答 → 存为笔记是「人筛 AI」；下一步可做「写笔记时浮出相关记忆」。

**不借什么**
- **默认本地大模型**：它假设用户愿意为隐私付算力。本项目的默认路径是「不配模型也能用」（离线抽取），
  模型是可选增强——这条不能跟着改，否则新用户第一步就卡在下载模型上。
- **自动双链/图谱**：需要稳定的 embedding 与较多笔记量才有价值。当前先做「搜索 + 标签」，
  等笔记过百篇再谈关联，否则只是给空库加装饰。

---

### 4. Khoj —— 「在你自己的文件上问答」，而不是「再建一个知识库」

**它做对了什么**
- 直接把用户已有的文件（pdf / markdown / org / 文本）纳为语料，而不是要求先导入到它的格式；
- 对话与语义检索是一等公民，模型可换（本地或云端）。

**借什么**
- **不搬运、只索引**：本项目的「知识库」已经是「指向目录」而不是「复制进数据库」，
  但界面上仍像「上传中心」。v1.19.0 把上传降级为「只读语料」，把**写记忆**的主路径让给智能体调 API，
  就是沿着这条线改的。
- **模型可换**：已有（任意 OpenAI 兼容端点 + 离线抽取兜底）。

**不借什么**
- **聊天机器人形态的首页**：Khoj 的核心是「随时问」。本项目的核心是「记忆」，
  所以首页保留「提问」但把它说成「今天想记住什么」，并让「已存记忆」始终一键可达。

---

### 5. Mem0 —— 记忆要分层，写入要收敛

**它做对了什么**
- 把「记忆」抽象成独立一层：写入（add）、检索（search）、按用户 / 会话 / 智能体作用域隔离；
- 记忆不是聊天记录，而是**被抽取、被压缩过的结论**，检索时按相关度取回。

**借什么**
- **记忆 ≠ 会话**：本项目 v1.19.0 把会话也搬进存储区（`threads/*.json`），但**没有**把它们混进笔记：
  会话是过程，笔记是结论；只有「存为笔记」才进记忆库。这条边界要在界面文案里一直说清。
- **作用域**：`NOTE_HOME` 就是单机场景下的「用户作用域」；MCP 的 7 个工具天然带这份边界。
- **写入要收敛**：规则摘要先抽结论再落盘（`digest_rule`），与本项目已有实现一致。

**不借什么**
- **向量库依赖**：Mem0 的价值依赖 embedding 质量。本项目坚持「零依赖也能用」，
  embedding 是可选加速（`RETRIEVAL=vector` 可开可关），不做成硬前置。

---

### 6. Logseq / Obsidian —— 文件是唯一真相，工具只是视图

**它做对了什么**
- 库就是一个文件夹，.md 是原始数据；换工具、换电脑、用 git 都能带走；
- 编辑体验优先：所见即所得、快速切换、全文搜索。

**借什么**（已落地）
- **存储区即库**：`~/记忆文档/` 下有 `notes/`、`threads/`、`index/`，`index/` 删了会自动重建；
- **可自由修改**：页面里能改原文（带乐观锁，别处改过会拒绝覆盖），也能用系统编辑器打开；
- **可迁移**：设置里换位置会提示「原位置还有 N 篇，要复制过来吗」。

**不借什么**
- **双向链接与图谱**：同上，等规模到了再说。
- **插件生态**：本项目的扩展点是 **MCP**，不是插件市场——接智能体比接插件更符合定位。

## 三、落到本项目的决策表

| 借鉴点 | 来源 | 落到哪里 | 状态 |
|---|---|---|---|
| 首启选目录、自动建库 | Reor | `GET/POST /api/settings/setup` + 首启弹窗 | v1.19.0 已做 |
| 文件即数据、可自由修改 | Reor / Obsidian / Logseq | `PUT /api/files/raw`、`POST /api/files/open`、页内编辑 | v1.19.0 已做 |
| 会话也不放浏览器 | Mem0（记忆分层）+ 本项目痛点 | `src/threadstore.py`、`/api/threads` | v1.19.0 已做 |
| 入库路径以智能体为主 | Khoj / Mem0 | 知识库页「让智能体来整理文档」引导 + 智能体面板 | v1.19.0 已做 |
| 存储占用说人话 | AnythingLLM（少即是多） | 存储面板改成「位置 + 四个数字」 | v1.19.0 已做 |
| 引用可解释、失败可诊断 | RAGFlow | 答案引用行 + 无答案原因 | 部分（引用已有，原因待细化） |
| 写作时浮出相关记忆 | Reor | 笔记编辑页侧栏「相关记忆」 | 待做（需 embedding + 一定笔记量） |
| 会话记录绑定知识库版本 | AnythingLLM | 会话文件里存 `kb_version`，导出时带出 | 待做 |
| 向量记忆层 | Mem0 | 可选 embedding 索引（已有开关） | 已有，但未用于「关联推荐」 |

**明确不采纳**：多工作区切换、RAG 参数控制台、默认本地大模型、双向链接图谱、插件市场。
理由统一是：**它们都在增加「先配置才能用」的成本，而本项目的卖点是「下载、建个目录、就能接智能体用」。**

## 四、这次界面为什么不再像 DeepSeek

对照下来，DeepSeek 的布局解决的是「多轮聊天」，而本项目的核心动作是「存 / 找 / 改记忆」。
所以 v1.19.0 做了三处方向性调整：

1. **配色从蓝白改成墨绿 + 米纸**：档案感，且不和聊天工具撞脸；标题换衬线，正文仍无衬线。
2. **首屏从「有什么可以帮你」改成「今天想记住什么」**：把动作从「聊天」拉到「沉淀」。
3. **存储面板从面积条 + 五段图例改成四个数字**：用户只想知道「多大、还剩多少」，
   不想学一套颜色编码。
