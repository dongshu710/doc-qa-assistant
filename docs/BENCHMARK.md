## 口径

- 语料是**合成**的条款文本，不是公开数据集：测的是实现开销，不是答案质量。
- 只测纯 Python 路径（默认配置）。装了 numpy/faiss 会更快，那是另一条路径。
- 延迟取 5 次中位数，已排除首次调用的懒初始化；计时期间关闭 GC（否则数字会跳 3 倍）。
- 每个用例在**独立子进程**里跑：同进程连续测会让后面的用例被前面的内存拖慢。
- 数字与 CPU 强相关，跨机器差 2–3 倍属正常；比较时请在同一台机器上重跑。

## 怎么读这些数字

- `vector`（纯 Python，含重排）在 20000 块时 51.3 ms，折合每千块 2.6 ms；按线性外推，5 万块约 128 ms。
- `bm25` 在 20000 块时 27.5 ms。词法检索的常数远小于向量内积，规模上去时它是更稳的兜底。
- 结论：按本次实测外推，5 万块仍在几百毫秒内，纯 Python 路径可用；再上一个数量级才需要考虑 `numpy`/`faiss`。
- 维度 256：5000 块时每千块 5.5 ms，20000 块时 5.7 ms —— 基本线性。
- 维度 1024：5000 块时每千块 21.0 ms，20000 块时 39.1 ms —— 基本线性。
- 笔记检索 1000 篇：首次 147.1 ms，缓存命中后 7.2 ms。首次的成本在分词，它随篇数线性增长；命中后只剩打分。
